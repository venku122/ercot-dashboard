# ERP-06 performance contract and measured optimization

The current controlled baseline fails the 2,500 ms median gate at **2,773 ms**. The candidate passes at **2,390 ms**, with **34 ms pointer p95**, **200 genuine changing readouts**, and **zero hover history requests**. Five candidate runs: 2,435 / 2,382 / 2,382 / 2,390 / 2,489 ms. Baseline: 2,886 / 2,773 / 2,751 / 2,755 / 2,787 ms. Full reviewed measurements are in `performance-measurements.json`; raw CDP network, CPU, heap and long-task profiles are under ignored `artifacts/post-release`.

Production Vite build, Chromium 149.0.7827.55, 1440×900, DPR1, Chicago timezone, five independent cold contexts, cache disabled, 4× CPU, 200,000 bytes/s down and 150 ms latency. The fixture remains byte-identical (`b9691591726a174644e5857045cda2a1f7503003afcf9e0835cab4cfe9a5c36a`), including native cadence and every series. Readiness requires both populated balance/headroom canvases and correct visible latest 71.0 GW demand, 90.1 GW capacity, 19.1 GW paired headroom. The baseline and candidate use the same single correctness predicate, avoiding accumulated protocol round trips from sequential assertions. The earlier campaign 3,018 ms report and older release reports remain historical context; their readiness/instrumentation differs and those figures are not the comparable baseline.

Number/date formatting constructed Intl instances inside repeated point/readout work. Tests demonstrated 100 constructions, then verified reuse with unchanged values. Hoisted chart/time formatters and a bounded precision-keyed number formatter cache avoid repeated setup. Specialist parser modules now load with the optional product that needs them; the main compressed response fell from 147,063 to 128,356 transferred bytes. Main bundle is 407.31 kB uncompressed, ChartCard 272.11 kB. Historical-context remains shared with App and is not claimed as a split chunk.

The chart chunk originally began about 1.2 s after initial main transfer. The generated HTML now preloads the same first-useful ChartCard chunk alongside the main asset. This advances the network dependency without changing lazy chart mounting or data requests. First-run CDP ScriptDuration fell 0.873→0.433 s and TaskDuration 1.482→0.951 s; LayoutDuration 0.173→0.154 s. Recorded long tasks went from ten (maximum190 ms) to five (maximum199 ms), and measured heap remained around15.4 MB. These are first-run profiles, not independent medians. Chart transfer stayed effectively unchanged (89,857→89,871 bytes). No renderer, worker, storage or cache framework was introduced.

Pointer latency is the existing conservative event-through-two-animation-frames proxy, not a paint timestamp. Pointer events drive the actual React cursor subscription; samples are retained only when populated readout strings change. The loop accumulates 200 changes (212 attempts) with a strict 1,000-attempt ceiling. Blank, unchanged, nonfinite or insufficient observations fail. Deliberately excessive cold/pointer and malformed-count fixtures prove rejection. The default browser test asserts the numeric result; `PERFORMANCE_REPORT_ONLY=1` is explicitly diagnostic and still records `pass:false` on a miss.

The real receiver path uses disposable SQLite, 336,964 stored observations: one year of native 300-second demand/capacity/legacy forecast and one day of native 4-second frequency. It serves production assets on loopback, without route fulfillment or network simulation. Thus it is a separate backend/query/JSON/browser measurement. All six bounded windows assert retained source counts and min/max, plus ≤1,200 returned points. Receiver code is unchanged; independently executed baseline→candidate query medians were67→110ms hourly average,210→237ms hourly min/max,95→88ms native raw105,120-point retrieval. These unchanged-code variations are not attributed as optimization. The existing receiver benchmark and its cache/minmax checks remain required. The disposable receiver exposes only fixture metadata through a helper endpoint; the browser clock is pinned to its native last observation so age does not erode coverage on reruns. All chart and range responses come through actual receiver HTTP/SQLite code. Browser regression checks cover populated balance, capacity and accessible Inspect at6h/24h/7d/30d/90d/1y; existing lifecycle/long-task/heap, canonical request and concurrency tests remain in place.

CI preserves existing receiver and browser budgets and adds an explicit controlled numeric homepage step. Hardware and Chromium differences can shift results; a miss is a failing check, never automatically qualified away. This local environment is macOS26.6.2 arm64, Node25.8.2, pnpm10.30.3. The final integrated source/UI ref must rerun the same controlled test before declaring campaign acceptance.
