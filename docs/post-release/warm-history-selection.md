# Retained history after an Overview selection change

The serialized Overview queue commits supply/demand, PRC and paired headroom before frequency history. A warm duration or comparison change can therefore retain the previous frequency points and statistics while the core plots already reflect the new selection. Previously that retained card exposed only a generic updating message and relabeled its comparison with the new mode.

Each successful historical batch now records its actual completed frontend request bounds and comparison context alongside the unchanged receiver metadata. A card retaining an incompatible context identifies the prior UTC window and comparison explicitly; its latest-value title and statistics table identify retained data, and the comparison dataset keeps its actual original mode. All real observations, statistics, coverage, interval bounds and source clocks remain intact. An ordinary running live refresh of the same duration and comparison retains its existing behavior. Missing request provenance is not invented.

The browser regression holds only the genuine frequency batch after an initial populated six-hour load, changes to 24 hours or changes previous-period comparison to previous-day, verifies unchanged prior statistics plus the exact prior window while pending, then releases the real fixture response and verifies the warning clears. A separate browser case advances the ordinary live clock with the same duration and holds that refresh, proving unchanged statistics remain without an incorrect prior-selection warning. Both cases use the existing native-cadence fixtures and no tolerance or snapshot changes.
